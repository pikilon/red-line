# Campaign mapper lessons (issue #482)

* A new map must be listed in `maps:` of `data/rules/globals.yaml`, or `build:data` reports "unknown map".
* Check `data/campaign/mission-scripts.yaml` (spec 62) for the mission id: some missions have no script. Goals live in `client/src/ui/campaign.ts` and use save labels only.
* Keep the map size and `starts` HQ cells equal to the old map so the save entities stay valid; only change `map:` in the save.
* Rivers need a shallow and a deep `water` entry with the same path; leave a bridge only where wanted.
* Add a feature check: `node --run build:data` validates placement; strict-mode ajv noise is harmless, filter with `grep -v "strict mode"`.
* Update the `globals.yaml` list, spec 48 §5 and a new §N map section, and commit `data/generated/*` if tracked changes appear.
* Snake Island (#482): a sea map needs no `blocked`; one deep `sea` rect plus a shallow fringe is enough, and `pier` is walkable over deep water. Water rects are inclusive `[x0, y0, x1, y1]`.
* When the saves put bases 45+ cells apart, the island must be as wide as the old HQ span: scale the real place up and say so in the spec.
* Most missions have no `mission-scripts.yaml` entry (only Hostomel so far): `grep -n "^campaign-" data/campaign/mission-scripts.yaml` first.
* Decoration ids that exist: `warehouse-barn`, `factory`, `house-small`, `shop`, `lamp-post`, `crate-stack`, `stone-wall`, `bush`, `dead-tree`, `lighthouse`, `pier`, `buoy`, `fishing-boat`.
* Mariupol (#482): roads may not touch deep water ("road on deep water"): stop road paths at the river banks and let a bridge feature carry the crossing; start rivers one row below a road. `pier` takes `at`, bridges take `from`/`to`.
* To view a map in a worktree run `node --run build:wasm` first (crates/sim/pkg is untracked), then start Vite after it exists.
* Bakhmut (#482): `trench` is a dug-in-match feature no map can place; use `stone-wall`/`hedge` lines. A river between the bases needs a bridge feature on the road; roads stop at the banks. `build:data` passed first try with 128x128 and ~150 features.
* Surovikin line (#482): ground materials that exist: grass, dirt, sand, rock, gravel, concrete. Linear obstacles (dragon's teeth) are one `stone-wall` per cell, generated by a small script. Keep scenery at least 3 cells from every save entity cell (check `atCenti`/100) and leave a gap in wall rows where a road crosses.
* Avdiivka (#482): `hedge` has a 2x1 footprint, so thin lines to every second cell (`stone-wall` and `fence` are 1x1); features take `at`, or `area` only with `density`/`seed`, so write lines one cell per entry with a small script. `elevation:` accepts `hills` and `ridges` for spoil tips. The one console 404 (`/audio-ref/zh-events.json`) is a git-ignored audio reference, not map data.
* The one 404 seen when loading any mission is `/audio-ref/zh-events.json`: the dev server probes an optional, git-ignored local audio reference pack (docs/audio-extension.md). It is expected; ignore it.
* Oreshnik (#482): a bridge needs land at both ends (`from`-1 and `to`+1 must be land), so leave a land strip between the river and the map edge; `crate-stack` and `lamp-post` have only 2 variants; map depots (e.g. [36, 20]) are footprints too, so halls cannot overlap them. Mission with no new script/goal changes needs only the save `map:` line.
* Kursk pipe (#482): a map-wide default `dirt` ground plus a few patches reads as frozen mud; the 'pipeline' is a thin `sand` rect. Scatter areas (trees) also block base footprints: the save test said "footprint blocked" until the dead-tree area stopped overlapping the Russian base (x 107-125, y 59-70). Spec section numbers collide when two map PRs are open at once: renumber the later one on merge.
* Kyiv (#482): generate the feature list with a small Python script, then fix what `build:data` reports ("footprint overlaps"): map depots (about 5x5) and your own neighbouring buildings are the usual culprits, and shops near a save entity (Patriot) must be dropped by hand. `features:` entries support `area` + `density` + `seed` for tree belts (`oak`, `poplar`, `birch`). Bridges `from`/`to` span the whole river width plus one land cell each side (river width 8 at x=64 took from 58 to 69). A map whose save bases sit on one row can still put a river between them: bases on opposite banks are fine, say so in the spec.
* Narva (#482): a 4-wide ring of `stone-wall` cells (one per cell, gaps where the road crosses) makes a readable castle; a church inside a small ring reads as a fortress tower, a concrete patch under factory halls as a plant yard. Keep Playwright quiet: `chromium.launch({ args: ["--mute-audio"] })` plus `&mute=1`, and kill Vite when done.
* Moskva (#482): reusing the old map's harbour block (quays, piers, cranes, containers from `demo-coast`) gives a port quarter that validates as is. Tree `area` belts also eat barn footprints: keep barns a row away from every scatter rect. Sea rects may overlap (deep over shallow) to carve a gulf or inlet.
* Kharkiv (#482): a tree `area` near an enemy factory (oak y 48-60 at x 100-124) blocked the Russian vehicle factory at [113, 60]: check every save building cell against scatter rects with `cargo test -p sim --test example_saves`. `build:data` may show errors from another map file if a concurrent agent edits the shared checkout: `git checkout` that file and rerun. Hint strings may mention a ford (`hint.balakliia`); the map has bridges instead, which is harmless.
